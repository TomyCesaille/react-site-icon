# Architecture

**Analysis Date:** 2026-04-19

## Pattern Overview

**Overall:** Single-component React library with detection state machine

**Key Characteristics:**
- One exported component (`SiteIcon`) with one entry point (`src/index.ts`)
- Three-state internal state machine: `loading` -> `found` | `missing`
- Zero runtime dependencies -- only React hooks and native `<img>` element
- `"use client"` directive injected at build time for RSC compatibility
- SSR-safe: renders fallback/detection img on server, resolves on client hydration

## Data Flow

**Favicon Detection Flow:**

1. Consumer renders `<SiteIcon domain="github.com" />` with optional `size`, `strategy`, `fallback`, `onResolved`
2. `normalizeDomain()` extracts hostname from input (handles full URLs, bare domains, whitespace)
3. `buildUrl()` constructs Google faviconV2 CDN URL with normalized domain and fetch size
4. Component renders based on `strategy`:
   - `lazy` (default): Shows `fallback` + hidden `<img>` for detection
   - `eager`: Shows visible `<img>` immediately (may briefly show globe)
   - `hidden`: Shows sized `<span>` placeholder + hidden `<img>` for detection
5. On `<img>` load: checks `naturalWidth > 16` (Google's globe fallback is exactly 16px)
   - `naturalWidth > 16`: favicon found -> transition to `found` state -> render visible `<img>`
   - `naturalWidth <= 16`: globe detected -> transition to `missing` state -> render `fallback`
6. On `<img>` error: transition to `missing` state -> render `fallback`
7. `onResolved(found: boolean)` callback fires after detection completes

**State Management:**
- Internal `useState<'loading' | 'found' | 'missing'>` drives render output
- Domain changes reset to `loading` via React's "adjust state during render" pattern (lines 107-110 in `SiteIcon.tsx`)
- `domainRef` prevents stale callbacks from previous domains
- `checkComplete` ref callback handles pre-loaded images (SSR hydration / browser cache)

**Size 16 Workaround:**
- Google's globe fallback is 16x16. If the consumer requests `size={16}`, the component fetches at 24px internally to distinguish real 16px favicons from the globe. The visible `<img>` still renders at 16x16.

## Key Abstractions

**SiteIcon Component:**
- Purpose: The entire public API of the library
- File: `src/SiteIcon.tsx`
- Pattern: `forwardRef` component with internal state machine
- Props interface: `SiteIconProps` extends `ComponentPropsWithoutRef<'img'>` (minus `src`, `width`, `height`, `onLoad`, `onError`)
- Ref forwarding: `forwardRef<HTMLImageElement, SiteIconProps>` -- ref attached in `found` state and `eager` loading state

**SiteIconSize Type:**
- Purpose: Constrains `size` prop to valid Google CDN sizes
- Values: `12 | 16 | 24 | 28 | 32 | 40 | 48 | 50 | 64 | 96 | 128`

**normalizeDomain():**
- Purpose: Extracts hostname from any input (full URL, bare domain, with/without protocol)
- Location: `src/SiteIcon.tsx` (line 41-50)
- Uses `new URL()` with protocol prefix trick

**buildUrl():**
- Purpose: Constructs the Google faviconV2 CDN URL
- Location: `src/SiteIcon.tsx` (line 52-53)

## Error Handling

**Strategy:** Silent degradation to fallback content

**Patterns:**
- Image load error (`onError`): Sets status to `missing`, renders `fallback` prop, calls `onResolved(false)`
- Globe detection (load with `naturalWidth <= 16`): Sets status to `missing`, renders `fallback` prop, calls `onResolved(false)`
- Empty/whitespace domain: Immediately enters `missing` state, renders `fallback`, calls `onResolved(false)`
- Invalid domain string: Passed through to CDN URL -- Google handles it (typically returns globe)
- Stale callbacks: `domainRef` check prevents acting on events from a previous domain after re-render
- No throws, no error boundaries, no console output

## Cross-Cutting Concerns

**Logging:** None. The library produces no console output.

**Validation:** Domain input is normalized, not validated. Invalid domains are passed to the CDN which returns a globe icon, detected as "missing."

**Authentication:** Not applicable.

**SSR Compatibility:**
- `"use client"` banner injected by tsup build config
- Server render produces fallback + detection img HTML
- `checkComplete` ref callback handles hydration when browser has pre-loaded the image

**Accessibility:**
- `alt=""` on all `<img>` elements (decorative image pattern)
- Rest props spread allows consumers to add `aria-label`, `role`, etc.
- Demo site uses `aria-label` on theme toggle, `htmlFor`/`id` on form elements
