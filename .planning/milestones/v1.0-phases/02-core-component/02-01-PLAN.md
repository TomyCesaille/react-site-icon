**normalizeDomain function (per D-17, D-18, COMP-07):**

```typescript
function normalizeDomain(input: string): string {
  const trimmed = input.trim();
  if (!trimmed) return '';
  try {
    return new URL(trimmed.includes('://') ? trimmed : `https://${trimmed}`).hostname;
  } catch {
    return trimmed;
  }
}
```

Keep as a module-scope non-exported function. Handles:
- `"github.com"` -> `"github.com"`
- `"https://github.com/user/repo?q=1"` -> `"github.com"`
- `"http://github.com:8080/path"` -> `"github.com"`
- Empty/whitespace -> `""` (triggers fallback per D-19)
- Punycode/Unicode pass through as-is per D-18

4. Event handlers (per COMP-08 naturalWidth, COMP-10 onError, COMP-11 onResolved, D-09):

```typescript
const handleLoad = (e: React.SyntheticEvent<HTMLImageElement>): void => {
  if (domainRef.current !== normalizedDomain) return; // stale (D-08)
  const found = e.currentTarget.naturalWidth > GOOGLE_DEFAULT_SIZE;
  setStatus(found ? 'found' : 'missing');
  onResolved?.(found);
};

const handleError = (): void => {
  if (domainRef.current !== normalizedDomain) return; // stale (D-08)
  setStatus('missing');
  onResolved?.(false);
};
```

Note on stale check: Compare `domainRef.current` against `normalizedDomain` (the current render's value). If they differ, this handler is from a previous domain's image load -- discard it.

Note: Do NOT wrap handleLoad/handleError in useCallback. The component is tiny and the memo overhead exceeds the benefit. The functions reference `normalizedDomain` and `onResolved` from closure -- they naturally update on re-render.

// STATUS: FOUND -- identical for all strategies (D-10, D-11, D-12, D-13)
if (status === 'found') {
  return <img ref={ref} src={src} width={size} height={size} alt="" {...rest} />;

// STATUS: LOADING -- differs by strategy
// Hidden detection img shared by lazy and hidden strategies
const detectionImg = (

    src={src}
    style={{ display: 'none' }}
    onLoad={handleLoad}
    onError={handleError}

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Consumer -> SiteIcon props | `domain` prop is untrusted string input from the consuming application |
| SiteIcon -> Google CDN | img src constructed from domain prop, loaded by browser (no fetch/XHR) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | `domain` prop -> img src URL | mitigate | Domain is passed through `new URL()` constructor which rejects dangerous schemes (javascript:, data:), then interpolated into a fixed Google CDN URL template `https://t1.gstatic.com/faviconV2?...&url=http://${domain}&size=...`. No user input reaches `dangerouslySetInnerHTML`. React JSX auto-escapes attribute values. |
| T-02-02 | Information Disclosure | `domain` prop leaks to Google CDN | accept | By design -- the component sends the domain to Google's faviconV2 CDN to retrieve the favicon. This is the core functionality. Consumers are aware they're using Google's CDN. No PII beyond the domain name. |
| T-02-03 | Spoofing | Malicious domain returns attacker-controlled image | accept | The img tag displays whatever Google's CDN returns for the domain. This is expected behavior -- the consumer chose to display that domain's favicon. No XSS risk since img src content cannot execute JavaScript. |
| T-02-04 | Denial of Service | Rapid domain prop changes trigger many CDN requests | accept | Each domain change triggers one CDN request (browser-managed). Stale detection cancellation (D-08) prevents acting on old results but cannot cancel in-flight browser image loads. This is standard browser img behavior. Rate limiting is the consumer's responsibility. |
</threat_model>
