**Critical implementation details:**

1. **simulateImageLoad helper** (per D-01, D-02):
```typescript
function simulateImageLoad(img: HTMLImageElement, naturalWidth: number): void {
  Object.defineProperty(img, 'naturalWidth', {
    value: naturalWidth,
    configurable: true,
  });
  fireEvent.load(img);
}

function simulateImageError(img: HTMLImageElement): void {
  fireEvent.error(img);
}
```

2. **Querying detection images**: Use `container.querySelector('img[style*="display"]')` for hidden detection imgs. Use `container.querySelector('img')` for visible imgs. Per Research Pattern 2, do NOT use `getByRole('img')` because `alt=""` gives presentation role.

3. **Re-query after state transitions**: After `simulateImageLoad()`, the component re-renders. Query for new img elements after the transition, not before. (Research Pitfall 4.)

4. **naturalWidth thresholds**: Found = `64` (any value > 16). Missing/globe = `16` (GOOGLE_DEFAULT_SIZE). These match the component's `e.currentTarget.naturalWidth > GOOGLE_DEFAULT_SIZE` check.

5. **CDN URL assertions**: Verify img src contains `t1.gstatic.com/faviconV2` and `url=http://{expected_hostname}`. Use `expect(img).toHaveAttribute('src', expect.stringContaining(...))`.

6. **SSR tests**: Import `renderToString` from `react-dom/server`. Call directly on `<SiteIcon>` JSX. Assert HTML string content with `toContain`/`not.toContain`.

7. **Stale detection test**: `render(<SiteIcon domain="a.com" />)` -> grab img ref -> `rerender(<SiteIcon domain="b.com" />)` -> `simulateImageLoad(oldImg, 64)` -> assert component is NOT in found state (still loading for b.com or has new detection img for b.com).

8. **Empty/whitespace domain**: Component sets status to 'missing' immediately when `normalizedDomain` is empty. No detection img rendered. Fallback shown immediately.

9. **No network requests (TEST-02)**: jsdom does not load images. `simulateImageLoad` uses `Object.defineProperty` + `fireEvent`, not real HTTP. No `fetch` or `XMLHttpRequest` calls anywhere in tests.

10. **Imports**:
```typescript

import { renderToString } from 'react-dom/server';
import { SiteIcon } from './SiteIcon';
import { createRef } from 'react';
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Test <-> Component | Tests must exercise real component behavior, not mock it away |
| Test <-> DOM | jsdom simulates browser; tests must not rely on jsdom-specific quirks that differ from real browsers |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | simulateImageLoad helper | mitigate | Helper sets naturalWidth via Object.defineProperty on the actual DOM element returned by container.querySelector, not a detached element. Each test re-queries the DOM after state transitions (Research Pitfall 4) to avoid operating on stale references. |
| T-03-02 | Repudiation | Test assertions | mitigate | Every test asserts observable DOM output (element presence, attribute values, text content), not internal component state. Tests use concrete matchers (toHaveAttribute, toHaveTextContent, toBeNull) not loose checks. |
| T-03-03 | Information Disclosure | Test file in build output | accept | tsconfig.json now includes test files, but tsup has explicit `entry: ['src/index.ts']` and `"files": ["dist"]` in package.json. Test files cannot appear in published package. Risk: negligible. |
| T-03-04 | Denial of Service | Flaky tests masking regressions | mitigate | No timers, no async waits, no network. All state transitions are synchronous via fireEvent. Tests are deterministic. |
</threat_model>
