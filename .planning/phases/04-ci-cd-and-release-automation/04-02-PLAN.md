```yaml
# NOTE: Enable branch protection in repo settings requiring this workflow
# to pass before merge to main. (Settings > Rules > Rulesets or Branch protection)

name: CI

on:
  pull_request:
  push:
    branches: [main]

jobs:
  ci:
    name: Quality Gates
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: 'npm'

      - run: npm ci

      - name: Lint
        run: npm run lint

      - name: Type check
        run: npm run typecheck

      - name: Unit tests
        run: npm run test

      - name: Export validation
        run: npm run test:exports

      - name: Format check
        run: npm run format:check

      - name: Build
        run: npm run build

      - name: Check bundle size
        run: |
          SIZE=$(gzip -c dist/index.js | wc -c)
          echo "Gzipped size: ${SIZE} bytes"
          if [ "$SIZE" -gt 1024 ]; then
            echo "::error::Bundle too large: ${SIZE} bytes (limit: 1024)"
            exit 1
          fi
```

Key details:
- D-04: Sequential fail-fast pipeline in exact order: lint, typecheck, test, test:exports, format:check, build. GitHub Actions stops on first failure by default.
- D-05: `node-version: 22` -- no matrix.
- D-06: Bundle size gate after build, fails if gzipped dist/index.js > 1024 bytes. Uses `::error::` annotation for GitHub UI.
- D-07: `cache: 'npm'` on setup-node.
- D-08: Actions pinned to major version tags (v4).
- D-09: Comment at top about branch protection.

Create `.github/workflows/release.yml` with the following exact content (per D-01, D-02, D-03, D-08, D-10):

```yaml
name: Release

on:
  push:
    branches: [main]

concurrency: ${{ github.workflow }}-${{ github.ref }}

permissions:
  contents: write
  pull-requests: write
  id-token: write

jobs:
  release:
    name: Release
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: 'npm'
          registry-url: 'https://registry.npmjs.org'

      - run: npm ci

      # This action has two modes:
      # 1. If .changeset/ has changeset files -> creates/updates a "Version Packages" PR
      # 2. If the "Version Packages" PR is merged -> runs the publish command
      #
      # FIRST PUBLISH: The very first npm publish must be done manually:
      #   1. Run `npm publish` locally to claim the package name
      #   2. Go to https://www.npmjs.com/package/react-site-icon/access
      #   3. Add GitHub Actions as trusted publisher:
      #      - Owner: jorislacance
      #      - Repository: react-site-icon
      #      - Workflow: release.yml
      #   4. After that, all publishes are automated via this workflow
      - name: Create Release PR or Publish
        uses: changesets/action@v1
        with:
          publish: npm run release
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

Key details:
- D-01: Changesets-driven publishing is the sole mechanism. changesets/action creates "Version Packages" PR, and merging it triggers `npm run release`.
- D-02: Comment block documents the manual first publish bootstrapping steps.
- D-03: No auto-merge -- the Version Packages PR is created for manual review.
- D-08: Actions pinned to major version tags.
- `permissions.id-token: write` enables OIDC Trusted Publishing. npm CLI >= 11.5.1 auto-detects this.
- `permissions.contents: write` allows pushing version bumps and creating GitHub releases.
- `permissions.pull-requests: write` allows creating/updating the Version Packages PR.
- `registry-url: 'https://registry.npmjs.org'` on setup-node is REQUIRED for OIDC -- without it, .npmrc is not configured for npm auth.
- `GITHUB_TOKEN` is for GitHub PR/release operations only, NOT for npm auth (OIDC handles npm auth).
- NO `NPM_TOKEN` secret -- OIDC replaces it entirely.
- Concurrency group prevents overlapping release attempts.

Create `.github/workflows/deploy.yml` with the following exact content (per D-11 through D-18):

```yaml
# NOTE: GitHub Pages must be enabled in repo settings with "GitHub Actions" as
# the source. (Settings > Pages > Source: GitHub Actions)

name: Deploy Demo Site

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  check:
    name: Check docs/ exists
    runs-on: ubuntu-latest
    outputs:
      exists: ${{ steps.check.outputs.exists }}
    steps:
      - uses: actions/checkout@v4
        with:
          sparse-checkout: docs

      - id: check
        run: echo "exists=$(test -d docs && echo true || echo false)" >> "$GITHUB_OUTPUT"

  quality:
    name: Quality Gates
    needs: check
    if: needs.check.outputs.exists == 'true'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: 'npm'

      - run: npm ci

      - name: Lint
        run: npm run lint

      - name: Unit tests
        run: npm run test

      - name: Build library
        run: npm run build

  build:
    name: Build Astro Site
    needs: quality
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: withastro/action@v6
        with:
          path: docs/
          node-version: 22

  deploy:
    name: Deploy to GitHub Pages
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```

Key details:
- D-11: The `check` job tests if `docs/` exists and sets a job output. All subsequent jobs have `if: needs.check.outputs.exists == 'true'` (inherited via `needs` chain -- `quality` has the explicit `if`, `build` needs `quality`, `deploy` needs `build`, so they all skip when docs/ is absent).
- D-12: `withastro/action@v6` handles install, build, and upload-pages-artifact.
- D-13: `path: docs/` tells withastro/action the Astro project root.
- D-14: Triggers on `push: branches: [main]` and `workflow_dispatch`.
- D-15: Concurrency group `pages` with `cancel-in-progress: true`.
- D-16: Quality gates job runs lint, test, build before the Astro build step.
- D-17: `npm run build` in quality job builds the library before the Astro site (which imports from it).
- D-18: Default GitHub Pages URL. Comment about enabling Pages in repo settings.
- D-05: `node-version: 22` on both setup-node and withastro/action (overrides withastro/action default of Node 24).
- D-08: Actions pinned to major version tags.
- `permissions.id-token: write` is required by GitHub Pages deployment (for OIDC token to deploy-pages action), not for npm.
- `sparse-checkout: docs` on the check job avoids full clone just to test directory existence.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions -> npm registry | OIDC token exchange for npm publish (no stored secrets) |
| GitHub Actions -> GitHub Pages | OIDC token for deployment (managed by GitHub) |
| PR event -> workflow execution | Untrusted PR content must not be injected into shell commands |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-03 | Elevation of Privilege | release.yml permissions | mitigate | Minimal permissions per workflow: CI has defaults (read-only), release has write + id-token, deploy has pages + id-token. No workflow has admin. |
| T-04-04 | Tampering | Action version hijack | accept | Actions pinned to major version tags per D-08. SHA-pinning not chosen for this OSS project. Risk is low for official GitHub and well-known actions. |
| T-04-05 | Tampering | PR title/body injection | mitigate | No `${{ github.event.pull_request.title }}` or `${{ github.event.pull_request.body }}` used in any `run:` block. All dynamic values are GitHub-controlled (secrets.GITHUB_TOKEN, steps.*.outputs.*). |
| T-04-06 | Elevation of Privilege | npm token compromise | mitigate | OIDC Trusted Publishing eliminates stored npm tokens entirely. No NPM_TOKEN secret exists. OIDC tokens are short-lived and scoped to the specific workflow run. |
| T-04-07 | Denial of Service | Overlapping deployments | mitigate | Concurrency groups on release.yml (`${{ github.workflow }}-${{ github.ref }}`) and deploy.yml (`pages` with `cancel-in-progress: true`) prevent resource contention. |
| T-04-08 | Spoofing | Unauthorized npm publish | mitigate | OIDC requires exact match of repository owner, name, and workflow filename on npm's trusted publisher config. Only release.yml from jorislacance/react-site-icon can publish. |
</threat_model>
