**In src/SiteIcon.tsx:**

The root cause: the `lazy` and `hidden` strategies render a detection `<img>` with `onLoad`/`onError` handlers during the "loading" state. When Astro SSR renders this img to HTML, the browser may fetch and cache the image before React hydrates. After hydration, React attaches the handlers but `onLoad` never fires because the image already loaded.

Fix by adding a ref to the detection img element and a useEffect that checks if the image has already loaded after mount:

1. Add a `useRef<HTMLImageElement>(null)` for the detection img (call it `detectionRef`).

2. Attach `detectionRef` to the hidden detection `<img>` elements in both `lazy` and `hidden` strategy branches. For `eager` strategy, the visible `<img>` already has the forwarded `ref`, so use a separate internal ref there too.

3. Add a `useEffect` (with dependency on `normalizedDomain` and `status`) that runs after mount/domain-change. Inside:
   ```typescript
   const img = detectionRef.current;
   if (img && img.complete && status === 'loading') {
     // Image already loaded (cached or SSR pre-fetch)
     if (img.naturalWidth > GOOGLE_DEFAULT_SIZE) {
       setStatus('found');
       onResolved?.(true);
     } else {
       setStatus('missing');
       onResolved?.(false);
     }
   }
   ```

4. For the `eager` strategy branch: use a separate internal ref (call it `eagerRef`). Combine it with the forwarded `ref` using a callback ref pattern:
   ```typescript
   const eagerInternalRef = useRef<HTMLImageElement>(null);
   ```
   Then in the eager `<img>`, use a callback ref that sets both:
   ```typescript
   ref={(el) => {
     eagerInternalRef.current = el;
     if (typeof ref === 'function') ref(el);
     else if (ref) ref.current = el;
   }}
   ```
   The post-mount useEffect should also check `eagerInternalRef.current` when strategy is 'eager'.

5. The useEffect for the post-mount check should look like:
   ```typescript
   useEffect(() => {
     const img = strategy === 'eager' ? eagerInternalRef.current : detectionRef.current;
     if (img && img.complete && status === 'loading') {
       if (img.naturalWidth > GOOGLE_DEFAULT_SIZE) {
         setStatus('found');
         onResolved?.(true);
       } else {
         setStatus('missing');
         onResolved?.(false);
       }
     }
   });
   ```
   Note: Run on every render (no dependency array) so it catches the first render after hydration. The `status === 'loading'` guard ensures it only runs once per detection cycle. This is intentional -- useEffect with deps could miss the window if deps don't change between SSR and hydration.

IMPORTANT: Keep all existing `onLoad`/`onError` handlers unchanged. They still handle the non-cached case (fresh loads). The useEffect is a safety net for already-loaded images.

IMPORTANT: The `key={normalizedDomain}` on `detectionImg` already causes React to remount the img on domain change, which resets `.complete`. This means the useEffect check is safe across domain changes.

IMPORTANT: Verify bundle size stays under 1KB gzipped after the change. Run `npm run build` and check dist/index.js size.

NOTE on test mechanics: In jsdom, the useEffect runs synchronously during `render()` when using @testing-library/react. So the approach is:
- Mock the img element's `.complete` property to return `true` BEFORE render
- Use a custom approach: after render, set `.complete = true` and `.naturalWidth = 64`, then trigger a re-render or use `act()` to flush effects
- Alternatively, mock the HTMLImageElement prototype's `complete` getter to return `true` for test setup

The simplest approach: after `render()`, get the detection img, set `Object.defineProperty(img, 'complete', { value: true, configurable: true })` and `Object.defineProperty(img, 'naturalWidth', { value: 64, configurable: true })`, then use `rerender()` with the same props (or a state-triggering mechanism) to run effects again. Actually, since the useEffect runs on every render with no deps array, the initial render's effect will check `.complete`. In jsdom, images are NOT auto-loaded, so `.complete` defaults to `false`. We need to set `.complete = true` before the effect runs. The cleanest approach:

Use `vi.spyOn(HTMLImageElement.prototype, 'complete', 'get').mockReturnValue(true)` before render, and also spy on `naturalWidth` getter to return the desired value. Then render normally -- the useEffect fires after mount and sees `.complete = true`. Clean up the spies after each test.
